# -- transitive pin held BELOW latest so a roster tool can run ------------
#
# pydantic 2.13.5 (the current latest) crashes on this interpreter, and it
# takes semgrep -- the SAST primary for 7 of the 103 metrics -- down with
# it. semgrep does not depend on pydantic directly; the chain is
# semgrep -> mcp -> pydantic-settings -> pydantic, three levels down.
#
# The failure is in a PRIVATE CPython API. pydantic calls
# typing._eval_type(..., prefer_fwd_module=True); 3.14 renamed that
# keyword to parent_fwdref as part of the PEP 649/749 typing rework, so
# the call raises TypeError. pydantic swallows it into a fallback whose
# `assert isinstance(value, ForwardRef)` then fails, because under PEP 649
# the FORWARDREF format yields a str. `import semgrep` still SUCCEEDS;
# only invoking it dies.
#
# pydantic 2.12.3 is the newest release that works here. This is the
# 'infrastructure is pinned to what actually runs' half of the policy:
# pydantic is not a roster tool, and a dark SAST primary would be a far
# larger distortion than a transitive held one minor release back.
# Verified: `semgrep --version` and a real `semgrep scan` both succeed,
# and `pip check` reports no broken requirements.
pydantic==2.12.3 ; python_version >= '3.14'
